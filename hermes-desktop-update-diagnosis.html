结论：失败是网络问题，不是 Hermes 自身故障
更新源是本地安装目录 git remote 指向的 GitHub fork（jinnnyang/hermes-agent，分支 moirai）。拉取时直连 github.com:443 被重置/超时，走本机 Clash 代理（127.0.0.1:7897）1.3 秒即成功。

为什么“检查更新”也失败
本套更新机制没有独立版本服务：检查更新 = git fetch 远端（有新提交则快进合并）。fetch 不通，检查与更新同时失败。本机 git 全局代理已按你的配置移除（gitconfig 无 http proxy），因此直连被网络环境重置。
